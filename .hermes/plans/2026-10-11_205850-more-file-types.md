# Knowledgebases — non-PDF inputs (DOCX · XLSX · PPTX · HTML · Markdown · text · email · images)

> **Status: future work — not implemented, not scheduled.** This plan exists so the
> work is unambiguous when it is picked up. For Hermes: implement task-by-task with
> the `subagent-driven-development` skill, never skipping the verification steps.

**Goal:** let Knowledgebases extract, index, search and cite source files other than
PDF, without changing anything about how PDFs behave today (all 225 verification
checks must stay green, and existing knowledge bases must keep working untouched).

**Architecture:** the pipeline already separates *extraction* (file → labelled text
blocks) from *storage* (blocks → SQLite + embeddings) from *presentation* (a hit's
locator → the original file at that place). Only the first and last are PDF-specific;
the middle is already format-agnostic apart from one word — "page". The plan widens
extraction to a format registry, generalises the page label to a **locator**, and
keeps `page` exactly as it is for PDFs so every existing citation, URL and knowledge
base stays valid.

**Tech stack:** Python 3.12 · PyMuPDF (PDF) · Docling ≥ 2.137 (multi-format + OCR) ·
SQLite + FTS5 · Chroma (or any registered vector backend) · Starlette + vanilla JS.

Consequences to respect: the vector id is derived as
`uuid5(NAMESPACE_URL, "pdfkb:" + chunk_id)` (`pdfkb/vectors.py:139`) — **changing that
string orphans every existing embedding**, so it must never be touched. The collection
name and embedding dimension must likewise stay as they are.

## Non-negotiable constraints

- A PDF must ingest, search, cite and preview **byte-for-byte as it does now**.
- Existing knowledge bases stay readable: migrations are additive `ALTER TABLE … ADD COLUMN`
  only, with defaults that reproduce today's behaviour.
- The **one-writer rule** holds: only the active knowledge base writes; every other is
  opened `readonly=True` (see the pdfkb skill).
- No new hard dependency. Multi-format extraction is an *optional extra*: Docling when
  installed, a light stdlib fallback otherwise, and a missing extra is reported in the
  ingest log, never a crash.
- Verification runs against an **isolated instance** (`PDFKB_DATA_DIR=$(mktemp -d)`,
  its own port) — never the user's live base.

## Task 1: a format registry in `extract.py`

**Objective:** one place that decides which file types are supported, by which
extractor, and what a "block" means for each.

**Files:** modify `pdfkb/extract.py`; test in the probe script.

**Step 1 — add the registry**

```python
# pdfkb/extract.py
FORMATS = {
    # ext: (label, preferred extractor, how to label a block)
    ".pdf":  ("PDF",      "docling",  "page"),      # block per page — unchanged
    ".docx": ("Word",     "docling",  "section"),
    ".doc":  ("Word",     "docling",  "section"),
    ".xlsx": ("Excel",    "docling",  "sheet"),
    ".xls":  ("Excel",    "docling",  "sheet"),
    ".pptx": ("PowerPoint", "docling", "slide"),
    ".html": ("HTML",     "docling",  "section"),
    ".htm":  ("HTML",     "docling",  "section"),
    ".md":   ("Markdown", "text",     "section"),
    ".txt":  ("Text",     "text",     "section"),
    ".eml":  ("Email",    "text",     "message"),
    ".png":  ("Image",    "docling",  "page"),      # OCR
    ".jpg":  ("Image",    "docling",  "page"),
    ".jpeg": ("Image",    "docling",  "page"),
    ".tif":  ("Image",    "docling",  "page"),
    ".tiff": ("Image",    "docling",  "page"),
}

def supported_suffixes():
    return tuple(sorted(FORMATS))
```

**Step 2 — generalise the extraction result**

Add `extract_blocks(path, extractor=None, ocr=False) -> (meta, blocks)` where a block is
`{"page": int | None, "label": str, "text": str}` and, for PDFs, `label == f"p.{page}"`,
`page` set — i.e. *exactly today's output plus one label*. Keep

```python
def extract_pages(path, extractor=None, ocr=False):
    meta, blocks = extract_blocks(path, extractor=extractor, ocr=ocr)
    pages = [{"page": b["page"], "text": b["text"]} for b in blocks if b["page"]]
    return meta, pages
```

as a compatibility shim so nothing else has to change in this task.

**Step 3 — verify** on the isolated instance: `extract_blocks` of a PDF returns the same
blocks `extract_pages` returns, `meta["npages"]` is unchanged, and the probe's existing
extraction checks (including "docling really extracts a PDF end to end") still pass.

**Step 4 — commit** `extract: format registry + block labels (PDF behaviour unchanged)`.

## Task 2: a locator instead of a bare page

**Objective:** store the human label of a block so a hit can point at "Sheet 2 · A1:F40"
or "Slide 7" the way it points at "p.12" now.

**Files:** modify `pdfkb/store.py` (`SCHEMA`, `add_document`, `page_context`, `export_text`,
`stats`), `pdfkb/web.py` (`_hit`, `/api/context`, `/api/pdf/{library}/{doc_id}`).

**Step 1 — additive migration** in `KB.__init__` next to the existing `extractor` migration:

```python
cols = {r["name"] for r in self.conn.execute("PRAGMA table_info(chunks)")}
if "locator" not in cols:
    self.conn.execute("ALTER TABLE chunks ADD COLUMN locator TEXT")
```

**Step 2 — write it** in `add_document`: `locator = block["label"]` (PDF ⇒ `f"p.{page}"`,
so the column is filled for old and new rows alike; leave `page` untouched).

**Step 3 — read it** in `page_context` (fall back to `f"p.{page}"` when `locator` is NULL,
which is what every existing row will be) and in `_hit()` add `h["locator"]`.

**Step 4 — verify:** a hit on a PDF reports `locator == "p.12"` and the modal is unchanged;
an existing knowledge base (pre-migration) still returns hits after the ALTER.

**Step 5 — commit** `store: locator column (additive; PDF hits unchanged)`.

## Task 3: actually extract the other formats

**Objective:** a DOCX/XLSX/PPTX/HTML/MD/TXT/EML file becomes labelled blocks.

**Files:** modify `pdfkb/extract.py` (`_extract_docling`, new `_extract_text`).

**Step 1 — Docling path.** Docling's `DocumentConverter` auto-detects the input format;
call it for every non-text suffix and map its result to blocks:

```python
def _extract_blocks_docling(path, ocr=False):
    from docling.document_converter import DocumentConverter, PdfFormatOption
    res = DocumentConverter().convert(str(path))
    doc = res.document
    blocks, n = [], 0
    for i, item in enumerate(getattr(doc, "texts", []) or [], start=1):
        text = _clean(getattr(item, "text", "") or "")
        if not text:
            continue
        n += 1
        # a page is carried when the format has pagination; otherwise the item number
        page = None
        prov = getattr(item, "prov", None) or []
        if prov and getattr(prov[0], "page_no", None):
            page = int(prov[0].page_no)
        blocks.append({"page": page, "label": f"p.{page}" if page else f"item {n}", "text": text})
    return blocks
```

(Table items become one block each; a spreadsheet sheet becomes a run of blocks —
cap at 200 blocks per document and say so in `meta["extractor_note"]`.)

**Step 2 — text path (no dependency at all).** For `.md`, `.txt`, `.eml`: read with
`encoding="utf-8", errors="replace"`, split on blank lines into section blocks, label
`f"§ {i}"`, and record `meta["extractor"] = "text"`.

**Step 3 — HTML without Docling.** `html.parser.HTMLParser` → strip tags, keep `<h1..h3>`
and `<p>` text; label by heading (`f"h: {heading}"`).

**Step 4 — verify** on the isolated instance: ingest a `.md`, a `.txt` and (if Docling is
present) a `.docx` generated with `python-docx`; assert `status == "added"`, `nchunks > 0`,
and that a phrase unique to the file is returned by `mode=keyword` **and** `mode=semantic`.

**Step 5 — commit** `extract: docx/xlsx/pptx/html/md/txt/e-mail via docling or stdlib`.

## Task 4: accept and store non-PDF uploads

**Objective:** the ingest route stops refusing anything that is not a PDF.

**Files:** modify `pdfkb/web.py:178` (the `.pdf` guard and the stored copy name),
`pdfkb/store.py` (`add_document` signature/`meta`), `web/index.html:108` (the pickers).

**Step 1 — the guard becomes a whitelist**

```python
from pdfkb.extract import supported_suffixes
SUFFIXES = supported_suffixes()

name = Path(filename or "upload").name
suffix = Path(name).suffix.lower()
if suffix not in SUFFIXES:
    return JSONResponse({"ok": False,
                         "error": f"unsupported file type: {name} ({', '.join(SUFFIXES)})"},
                        status_code=400)
dest = src_dir / f"{Path(name).stem}-{hashlib.sha1(data).hexdigest()[:8]}{suffix}"
```

**Step 2 — the store keeps the real extension** and stores `kind` (from `FORMATS`) and
`nunits` (block count) in `documents` (another additive migration); `npages` keeps its
meaning for PDFs and is `0` for non-paginated formats.

**Step 3 — the pickers advertise it**:
`accept=".pdf,.docx,.doc,.xlsx,.xls,.pptx,.html,.htm,.md,.txt,.eml,.png,.jpg,.jpeg,.tif,.tiff"`,
and the Sources help text lists the same set from one place.

**Step 4 — verify:** uploading a `.md` stores it under `sources/` with its real suffix,
indexes it, and a `.exe` is refused with a clear message and **no** file written.

**Step 5 — commit** `web: accept and store the supported file types`.

## Risks, tradeoffs, open questions

1. **Docling coverage.** Docling handles DOCX/XLSX/PPTX/HTML/AsciiDoc/images well, but
   legacy `.doc`/`.xls` are hit-and-miss and its OCR of images needs Tesseract. Decide per
   format whether "supported" means *guaranteed* or *best effort*, and make the ingest log
   say which happened. `.doc`/`.xls` may be better declared unsupported than half-working.
2. **What is a "page" without pages?** The locator scheme (section / sheet range / slide)
   is a product decision. Proposal: one block per sheet range for spreadsheets (cap ~200
   blocks per file), one block per slide for decks, one block per heading section otherwise.
3. **Preview fidelity.** Office documents cannot be previewed in an iframe; the honest
   answer is a download link plus the extracted text in the modal. Do not promise a
   rendering we cannot do.
4. **FTS5 content.** `chunks_fts` is filled from `chunks.text` — unchanged, so keyword
   search works for new formats for free.
5. **Do not touch** `uuid5(… "pdfkb:" + chunk_id)` in `pdfkb/vectors.py`, the collection
   name, or the embedding model: any of those changes orphans existing embeddings
   (`collection_match: false`).
6. **Sizing.** A 40 MB XLSX can produce tens of thousands of blocks. Cap blocks per
   document, and make the cap visible in the ingest line rather than silently truncating.
7. **Migration order.** Ship Tasks 1–2 (registry + locator) before the extraction work:
   they are behaviour-preserving, so a regression there is easy to spot against the
   existing 225 checks.
